### 1. 아키텍처 설계 능력: **85/100점** ⭐⭐⭐⭐

**평가:**
- DDD 원칙을 이해하고 적용함
- 레이어 분리가 명확함 (Controller, Domain, DTO, Global, Infra)
- 이벤트 기반 아키텍처로 도메인 간 결합도 낮춤
- Facade, Strategy, Policy 패턴 등 적절히 활용
- **PromptSearchContext** 같은 독특한 설계 아이디어

**면접관 관점:**
> "아키텍처 설계 능력이 뛰어납니다. 단순히 기능을 구현하는 것이 아니라, 확장 가능하고 유지보수하기 쉬운 구조를 고민한 흔적이 보입니다."

---

### 2. 성능 최적화: **90/100점** ⭐⭐⭐⭐⭐

**평가:**
- Redis 캐싱 전략이 체계적 (실시간 카운트 + 배치 동기화)
- 커서 기반 페이징으로 대용량 데이터 처리
- JdbcTemplate 배치 업데이트 활용
- Lua 스크립트로 원자적 연산 보장
- 인덱스 전략이 실제 쿼리 패턴을 고려함

**면접관 관점:**
> "성능 최적화에 대한 이해도가 높습니다. 단순히 캐싱만 하는 것이 아니라, 성능과 일관성의 트레이드오프를 고려한 하이브리드 방식을 구현했습니다."

---

### 3. 코드 품질: **75/100점** ⭐⭐⭐

**평가:**
- 일관된 코딩 스타일 (Lombok, Builder 패턴)
- 예외 처리 체계화 (ErrorCode enum, GlobalExceptionHandler)
- 주석과 JavaDoc으로 의도 명확화
- 하지만 일부 하드코딩된 값들 (BATCH_SIZE, SCHEDULE_DELAY_MS)
- TODO 주석 발견 (운영팀 알림 등)

**면접관 관점:**
> "코드 품질은 전반적으로 좋지만, 설정 값 외부화나 미완성 기능(TODO)이 눈에 띕니다."

---

### 4. 보안: **90/100점** ⭐⭐⭐⭐⭐

**평가:**
- Rate Limiting 구현 (Lua 스크립트 활용)
- XSS 방지 (OWASP HTML Sanitizer)
- JWT + OAuth2 통합
- 토큰 버전 관리로 무효화 지원
- **도메인별 보안 정책 분리**: Auth는 인증/인가 인프라만 제공, 각 도메인은 자신의 보안 정책을 가짐
  - `CommentPermissionChecker`: 댓글 도메인의 권한 체크
  - `FollowBlockPolicy`: 팔로우 도메인의 차단 정책
  - 각 도메인 서비스에서 자신의 권한 체크 수행

**면접관 관점:**
> "보안 설계가 매우 잘 되어 있습니다. Auth 도메인은 인증/인가의 기본 메커니즘만 제공하고, 각 도메인은 자신의 보안 정책을 가지도록 설계했습니다. 이는 DDD 원칙에 부합하며, 도메인 간 경계를 명확히 유지합니다. 만약 모든 보안 정책을 Auth에 몰아넣으면 오히려 God Object가 되고 도메인 경계가 깨집니다."
