## 🔗 배포 문제와의 연관성

### 코드 문제 → 배포 문제 해결 방향

**코드 문제를 해결하면 배포 문제도 해결되는 경우:**
- ✅ **항목 10 (PromptPersistenceService)** → [`배포_시_문제점_분석.md`](./배포_시_문제점_분석.md) 항목 11과 동일 문제
  - 트랜잭션 전파 전략 문제를 코드에서 해결하면 배포 문제도 해결됨

**코드 문제를 해결하면 배포 문제도 부분적으로 해결되는 경우:**
- ⚠️ **항목 22 (NotificationServiceImpl)** → [`배포_시_문제점_분석.md`](./배포_시_문제점_분석.md) 항목 5와 관련
  - 코드 설계 개선 시 알림 시스템 확장성 향상되어 배포 문제 해결에 도움됨
  - 단, 실제 알림 발송 로직 구현은 별도 작업 필요

**코드 문제를 해결해도 배포 문제가 자동으로 해결되지 않는 경우:**
- 대부분의 배포 문제는 **인프라/설정/운영** 문제입니다
- 예: 환경 변수 설정, DB 마이그레이션 도구, ShedLock 테이블 생성, Redis/RabbitMQ 호스트 설정 등

### 배포 문제 → 코드 문제 해결 방향

**배포 문제를 해결하면 코드 문제도 해결되는 경우:**
- ✅ **배포 항목 11 (트랜잭션 전파 전략)** → 코드 항목 10과 동일 문제

**배포 문제를 해결해도 코드 문제가 자동으로 해결되지 않는 경우:**
- ⚠️ **배포 항목 5 (알림 시스템)** → 코드 항목 22와 관련
  - 알림 기능을 구현해도 설계 문제(책임 분리)는 별도로 해결 필요

> 💡 **배포 시 문제점은 별도 문서로 관리됩니다**  
> 상세한 배포 관련 문제점과 해결 상태는 [`배포_시_문제점_분석.md`](./배포_시_문제점_분석.md)를 참조하세요.

## 코드 품질 이슈

### 🔧 설정 및 Bean 관리

#### 1. RebuildStatusServiceConfig
**파일**: `src/main/java/org/example/sharedprompts/domain/admin/maintenance/config/RebuildStatusServiceConfig.java`

**문제점**: 두 개의 Bean 메서드에 모두 `@Primary` 어노테이션이 적용되어 있음. 조건부로 하나만 활성화되지만, 같은 타입에 두 개의 `@Primary`는 Spring 컨테이너에서 모호성을 야기할 수 있음

**해결 방안**: 조건부 활성화 시 `@Primary`는 하나만 유지하거나 `@ConditionalOnProperty`만 사용하는 것이 더 명확함

**브랜치**: `refactor/admin-rebuild-status-primary-conflict`

#### 8. AuthServiceImpl (✅ 리팩토링 완료)
**파일**: `src/main/java/org/example/sharedprompts/domain/auth/service/AuthServiceImpl.java`

**문제점**: 
- 과도한 의존성 주입 (12개) - 다른 서비스들(6개)의 2배
- 단일 책임 원칙(SRP) 위반 가능성
- 테스트 복잡도 증가

**해결 방안**: 
- `SignUpService`: 회원가입 관련 로직 통합 (PasswordEncoder, PasswordStrengthValidator, UserRegistrationService)

- `TokenSecurityService`: 토큰 보안 검증 통합 (TokenSecurityValidator, TokenSecurityResultHandler)
- 의존성 12개 → 8개로 감소 (33% 감소)

**브랜치**: `refactor/auth-service-dependency-reduction`

## 배포 관련 문제점

배포 시 발생할 수 있는 문제점들을 정리했습니다. 대부분의 배포 문제는 **인프라/설정/운영** 문제로 코드 문제와 별개입니다.

### ⚠️ 양방향 해결 관계 요약

**양방향으로 해결 가능한 문제:**
- ✅ **트랜잭션 전파 전략** (코드 항목 10 ↔ 배포 항목 11)
  - 코드에서 해결 → 배포 문제 해결
  - 배포 문제 해결 → 코드 문제 해결

**일방향으로만 해결 가능한 문제:**
- ⚠️ **알림 시스템** (코드 항목 22 ↔ 배포 항목 5)
  - 코드 설계 개선 → 배포 문제 부분 해결 (확장성 향상)
  - 배포 문제 해결(기능 구현) → 코드 설계 문제는 별도 해결 필요

**서로 무관한 문제:**
- 대부분의 배포 문제는 **인프라/설정/운영** 문제로 코드 문제와 무관
- 예: 환경 변수 설정, DB 마이그레이션 도구, ShedLock 테이블 생성, Redis/RabbitMQ 호스트 설정 등

> ⚠️ **중요**: 코드 문제만 해결해서는 배포 문제가 해결되지 않습니다!  
> 대부분의 배포 문제는 **인프라/설정/운영** 작업이 필요합니다.

### 23. 필수 환경 변수 누락으로 인한 애플리케이션 시작 실패 ✅ 해결됨
**위치**: `src/main/resources/application.yml`

**문제점**:
- 필수 환경 변수에 기본값이 없어 설정 누락 시 애플리케이션이 시작되지 않음
- 다음 환경 변수들이 필수이지만 기본값이 없음:
  - `JWT_SECRET`, `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME`, `SPRING_DATASOURCE_PASSWORD`
  - `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`, `KAKAO_CLIENT_ID`, `KAKAO_CLIENT_SECRET`
  - `CORS_ALLOWED_ORIGINS`, `OAUTH2_REDIRECT_FRONT_URL`, `OAUTH2_FAILURE_REDIRECT_URL`, `OAUTH2_SALT`, `GOOGLE_GEMINI_API_KEY`

**영향**: 애플리케이션이 시작되지 않아 서비스 중단

**해결 완료**:
- ✅ `EnvironmentValidator` 클래스 추가: 애플리케이션 시작 시 필수 환경 변수 자동 검증
- ✅ 누락된 환경 변수가 있으면 애플리케이션 시작 실패 (IllegalStateException)

**브랜치**: `infra/environment-validation`
